# Ресторан MOOD — сайт для бенкетів

Адаптивний сайт бенкетного напряму ресторану MOOD на React + Vite.

## Запуск локально

```bash
npm install
npm run dev
```

## Поле номера телефону

У калькуляторі бенкету та формі зворотного дзвінка код країни `+380` показаний як фіксований префікс. Відвідувач вводить лише 9 цифр українського номера. Літери та інші символи не залишаються в полі; зайві цифри не додаються. Можна вставити номер у форматі `+380 67 123 45 67` або `0671234567` — поле нормалізує його до 9 цифр після `+380`. Перехід до підтвердження та надсилання заявки недоступні, доки номер не містить рівно 9 цифр. Сервер повторно перевіряє номер і нормалізує його до E.164 (`+380XXXXXXXXX`).

## Калькулятор

Калькулятор працює як модальне вікно. Він збирає тип події, дату, кількість гостей, бажаний формат меню, додаткові побажання та контакти. Ціни бенкетного меню не вигадувалися: у підсумку зазначено, що вартість узгоджується індивідуально. Після отримання затверджених тарифів можна підключити точний автоматичний розрахунок.

## Надсилання заявок у Telegram

Сайт має серверний endpoint `POST /api/lead`. Токен бота зберігається тільки на сервері у файлі `.env` і не потрапляє до браузера.

### 1. Створіть Telegram-бота

1. У Telegram відкрийте `@BotFather`.
2. Надішліть `/newbot`, задайте назву та username бота.
3. Скопіюйте отриманий токен. Не публікуйте його та не додавайте в код фронтенду.
4. Відкрийте створеного бота зі свого акаунта MOOD та натисніть Start або надішліть `/start`.

### 2. Додайте токен у локальний проєкт

У кореневій папці, поруч із `package.json`, скопіюйте `.env.example` і назвіть копію `.env`.
Відкрийте `.env` і заповніть:

```env
TELEGRAM_BOT_TOKEN=вставте_токен_від_BotFather
MOOD_DATA_ENCRYPTION_KEY=згенерований_32_байтовий_ключ
TELEGRAM_CHAT_ID=
```

### 3. Дізнайтеся chat_id

Зберігши токен у `.env`, у терміналі VS Code виконайте:

```powershell
npm.cmd run telegram:chat-id
```

Команда покаже `chat_id` приватного чату, у якому ви натиснули Start. Скопіюйте його в `.env`:

```env
TELEGRAM_BOT_TOKEN=ваш_токен
TELEGRAM_CHAT_ID=486227325
TELEGRAM_GROUP_CHAT_ID=
```

`TELEGRAM_CHAT_ID` залиште зі своїм особистим ID `486227325`. Це збереже особисті сповіщення. Для паралельної доставки заявок у групу менеджерів заповніть окрему змінну `TELEGRAM_GROUP_CHAT_ID`. Сервер надсилає кожну заявку всім унікальним налаштованим отримувачам.

### 4. Створіть групу менеджерів MOOD

1. У Telegram створіть нову групу з назвою **MOOD — Банкетні заявки**.
2. Додайте до групи менеджерів, які мають бачити заявки.
3. Додайте бота `@MoodBanquet_bot` як учасника. Переконайтеся, що в нього є право надсилати повідомлення.
4. У групі надішліть команду ` /start@MoodBanquet_bot ` (без пробілів на початку та в кінці). Це дасть змогу знайти групу навіть якщо в бота ввімкнений режим приватності.
5. У терміналі проєкту виконайте `npm.cmd run telegram:chat-id`. У списку знайдіть чат із типом `group` або `supergroup` і назвою **MOOD — Банкетні заявки**.
6. Скопіюйте його `chat_id` — для супергруп це зазвичай від’ємне число, часто з префіксом `-100`. Не використовуйте особистий ID замість групового.
7. Відкрийте `.env` і вставте це число в `TELEGRAM_GROUP_CHAT_ID`, залишивши особистий `TELEGRAM_CHAT_ID=486227325` без змін.

Приклад налаштування (груповий ID нижче — лише формат, не реальне значення):

```env
TELEGRAM_BOT_TOKEN=ваш_токен
TELEGRAM_CHAT_ID=486227325
TELEGRAM_GROUP_CHAT_ID=-1001234567890
```

### 5. Перевірте доставку

```powershell
npm.cmd run telegram:test
```

Тестове повідомлення має надійти в особистий чат і в групу (якщо `TELEGRAM_GROUP_CHAT_ID` налаштований). Після зміни `.env` перезапустіть сервер. Після цього запускайте сайт:

```powershell
npm.cmd run dev
```

Калькулятор бенкету та форма зворотного дзвінка надсилатимуть заявки в особистий чат і групу менеджерів, якщо обидва отримувачі налаштовані. Якщо Telegram не відповість, користувач побачить повідомлення про помилку, а форма не покаже неправдиве підтвердження успіху.

### 5. Публікація сайту

Локальний `localhost` доступний лише на вашому комп’ютері. Щоб заявки від відвідувачів публічного сайту надходили в Telegram, потрібно розмістити сайт разом із Node.js-сервером на хостингу, який підтримує Node.js. На хостингу додайте `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` і `TELEGRAM_GROUP_CHAT_ID` як environment variables. Не завантажуйте `.env` у публічний репозиторій або до статичного хостингу.

Команди для production-хостингу:

```bash
npm install
npm run build
npm start
```

`.env` додано до `.gitignore`, щоб токен випадково не потрапив у Git.

## Формат повідомлень про заявки в Telegram

Усі заявки надсилаються за єдиним шаблоном MOOD: тип звернення, ім’я, телефон, подія, дата, кількість гостей, меню, додаткові побажання, коментар, час отримання та джерело. Поля, які гість не заповнив або які не передбачені конкретною формою, залишаються порожніми — без підстановки вигаданих значень.


## Керування заявками в Telegram

Для керування заявками потрібні `TELEGRAM_BOT_TOKEN` і `TELEGRAM_GROUP_CHAT_ID`. Особисті сповіщення на `TELEGRAM_CHAT_ID` зберігаються. Керування виконується лише в групі **MOOD — Банкетні заявки**, щоб не створювати дві незалежні картки однієї заявки.

### Сценарій обробки заявки

1. **Нова заявка** — сайт надсилає картку у групу зі статусом `🆕 Нова заявка` і кнопкою `🟡 Взяти в роботу`.
2. **Взяти в роботу** — бот закріплює заявку за менеджером, записує Telegram ID та час. Інший менеджер не може перехопити вже призначену заявку.
3. **Зателефонувати гостю** — відповідальний менеджер натискає кнопку в картці заявки. Бот викликає Telegram Bot API `sendContact` і надсилає у групу нативну картку контакту гостя з його ім’ям та номером. Під карткою є кнопки результату.
4. **Результат спроби зв’язку** — відповідальний менеджер обирає один варіант:
   - `✅ Дзвінок здійснено` — менеджер підтверджує, що здійснив дзвінок;
   - `📵 Не відповів` — спробу зафіксовано, заявка залишається в роботі;
   - `🔁 Передзвонити пізніше` — спробу зафіксовано та заплановано нагадування.
5. **Повторний дзвінок** — після `Не відповів` або `Передзвонити пізніше` бот надсилає нагадування відповідальному менеджеру в особистий чат і в групу. Менеджер може знову відкрити картку контакту через кнопку `📞 Зателефонувати гостю`.
6. **Фінальний статус** — після хоча б однієї зафіксованої спроби менеджер може обрати `✅ Підтверджена` або `❌ Відхилена`. Після цього заявка закривається і кнопки керування прибираються.

**Обмеження Telegram:** `sendContact` надсилає нативну картку контакту. Сам Telegram Bot API не підтверджує факт GSM-з’єднання або тривалість телефонної розмови. Кнопки результату фіксують підтверджену менеджером дію. Це процесний контроль, а не інтеграція з мобільним оператором.

### Картка контакту та компактна історія

- Для кожної заявки в групі зберігається ID останньої надісланої картки контакту гостя.
- Під час повторної спроби бот спочатку надсилає нову картку контакту, а після успішної доставки видаляє попередню. Після завершення операції в групі залишається одна актуальна картка контакту на заявку. Якщо Telegram не дозволить видалити попереднє повідомлення, сервер запише помилку в журнал і спробує прибрати кнопки зі старої картки.
- У тексті заявки за замовчуванням показуються лише дві останні спроби зв’язку та дві останні дії історії.
- Кнопки `📞 Усі спроби зв’язку (N)` і `🗂 Уся історія дій (N)` відкривають повний список сторінками по 10 записів. Навігація `Старіші` / `Новіші` дає змогу переглянути всі попередні записи, а кнопка `Згорнути` повертає до двох останніх.
- Розгортання історії не змінює статус заявки й не передає права керування іншому менеджеру.

### SLA та нагадування

- Після надходження заявки запускається відлік першої спроби зв’язку.
- Якщо протягом 5 хвилин не зафіксовано результат першої спроби дзвінка, бот надсилає нагадування в групу.
- Після `Не відповів` або `Передзвонити пізніше` бот планує повторне нагадування на 30 хвилин.
- Значення можна змінити у `.env`:

```env
TELEGRAM_FIRST_CALL_SLA_MINUTES=5
TELEGRAM_CALLBACK_REMINDER_MINUTES=30
```

Перше значення — час до SLA-нагадування після нової заявки. Друге — інтервал до нагадування про повторний дзвінок. Обидва значення задаються в хвилинах.

### Реєстрація та права менеджерів

Кожен менеджер має пройти особисту реєстрацію в боті перед керуванням заявками:

1. Менеджер має бути учасником групи **MOOD — Банкетні заявки**.
2. У групі надсилає `/register` або відкриває посилання реєстрації.
3. У приватному чаті з `@MoodBanquet_bot` читає повідомлення про обробку даних і натискає `Надаю згоду`.
4. Натискає `Надіслати мій номер телефону`. Telegram передає боту власний контакт менеджера.
5. Бот зберігає Telegram ID, ім’я, прізвище, username (якщо є), телефон та час згоди/реєстрації.

Telegram дозволяє кнопку `request_contact` лише в особистому чаті з ботом. Бот має бути адміністратором групи, щоб перевіряти членство менеджерів через `getChatMember`.

Кнопки керування доступні лише зареєстрованому менеджеру, який є учасником групи. Заявкою керує менеджер, який першим узяв її в роботу. Тільки він може надсилати контакт гостя, фіксувати результат дзвінка та закривати заявку.

Менеджер може оновити реєстрацію командою `/register` у приватному чаті. Для видалення власного профілю — `/delete_my_data`. Історія вже виконаних дій у заявках після видалення профілю знеособлюється.

### Налаштування Telegram

У `.env` мають бути задані:

```env
TELEGRAM_BOT_TOKEN=токен_від_BotFather
MOOD_DATA_ENCRYPTION_KEY=згенерований_32_байтовий_ключ
TELEGRAM_CHAT_ID=486227325
TELEGRAM_GROUP_CHAT_ID=-100XXXXXXXXXX
TELEGRAM_BOT_USERNAME=MoodBanquet_bot
TELEGRAM_FIRST_CALL_SLA_MINUTES=5

```

Не публікуйте `.env` і не надсилайте токен бота в чат. Файл `.env` виключено з Git через `.gitignore`.

### Збереження історії

Заявки, менеджери та стан Telegram зберігаються в `data/` у зашифрованому AES-256-GCM форматі. Для production обов'язково задайте `MOOD_DATA_ENCRYPTION_KEY` як 64-символьний hex-ключ або 32-байтовий base64-ключ. Створіть його один раз командою `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`, зберігайте тільки в environment variables/секрет-сховищі та не змінюйте без процедури міграції. Старі незашифровані JSON-файли автоматично мігрують під час першого запуску з ключем. Каталог `data/` виключено з Git, оскільки він містить персональні дані.

### Запуск і діагностика

```powershell
npm.cmd install
npm.cmd run dev
```

- Сервер Node.js має працювати постійно, інакше бот не оброблятиме кнопки та не надсилатиме нагадування.
- Для одного токена бота має працювати лише один процес long polling. Якщо паралельно запущено інший процес або webhook, Telegram може повернути `409 Conflict`.
- Скрипт `npm.cmd run telegram:chat-id` також використовує `getUpdates`; запускайте його із зупиненим сервером, щоб не конфліктувати з long polling.
- Нагадування перевіряються сервером кожні 15 секунд. Після перезапуску сервера невідправлені нагадування продовжують відстежуватися за даними у `data/leads.json`.
- Кнопка `Зателефонувати гостю` надсилає контакт через `sendContact`. Після цього під контактною карткою менеджер має вручну зафіксувати результат. Telegram не може сам прочитати історію дзвінків смартфона.


## Виправлення Telegram-картки контакту

У цій версії додано визначення `callResultKeyboard`, яке формує кнопки результату під нативною карткою контакту гостя: «Дзвінок здійснено», «Не відповів» і «Передзвонити пізніше». Це виправляє помилку `callResultKeyboard is not defined`, яка блокувала надсилання контакту.

Окремий браузерний тестовий комплекс перевіряє сайт у Chromium на desktop, tablet та двох мобільних розмірах, включно з калькулятором, формою зворотного дзвінка, читабельністю, контрастністю через axe-core, основними touch-цілями та базовими метриками продуктивності.

Інструкція: [QA.md](./QA.md).

Установка браузера та запуск у Windows PowerShell:

```powershell
npm.cmd install
npm.cmd run qa:install
npm.cmd run qa
```

Для перегляду HTML-звіту: `npm.cmd run qa:report`. Для затвердження baseline-візуальних скриншотів: `npm.cmd run qa:visual:baseline`, наступне порівняння: `npm.cmd run qa:visual`.

QA запускає Vite напряму на localhost, перехоплює запити форм і не запускає Telegram polling. Автоматичні браузерні тести не створюють реальних заявок і не надсилають повідомлень у робочі Telegram-чати.
