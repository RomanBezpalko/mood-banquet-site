# MOOD QA — автоматизоване тестування сайту

## Що перевіряє набір

- Завантаження головної сторінки та наявність основних секцій.
- Внутрішню структуру, посилання на меню, Instagram, телефон.
- Горизонтальне переповнення сторінки на desktop / tablet / mobile.
- Розміри основних кнопок і контроль читабельності тексту.
- Доступність через axe-core (WCAG 2.0/2.1 A/AA).
- Роботу плаваючого блоку зв'язку та мобільної навігації.
- Повний сценарій калькулятора, включно з перевіркою 8/9 цифр у телефоні.
- Форма зворотного дзвінка.
- Помилки JavaScript у браузерній консолі.
- Скриншоти та JSON-звіти для кожного viewport.

## Безпечний режим

Playwright запускає Vite напряму на `127.0.0.1:4173`, а не `server.mjs`. Тому під час `npm run qa` бот не запускає long polling та не надсилає повідомлень у реальні Telegram-чати. Запити браузера до `/api/lead` перехоплюються Playwright і повертають тестову відповідь. У `MOOD QA` не використовуються реальні заявки.

## Встановлення (Windows PowerShell)

У корені проєкту, де лежить `package.json`:

```powershell
npm.cmd install
npx.cmd playwright install chromium
```

Якщо браузер Playwright уже встановлений, друга команда не потрібна.

## Запуск усіх браузерних перевірок

```powershell
npm.cmd run qa
```

## Візуальні порівняння

Після ручного перегляду скриншотів першого звіту можна створити затверджені еталони:

```powershell
npm.cmd run qa:visual:baseline
```

Наступні запуски порівнюють поточну сторінку з еталонами:

```powershell
npm.cmd run qa:visual
```

Порівняння перевіряє головну сторінку та відкритий калькулятор на всіх чотирьох viewport. Зображення приховуються в baseline-знімках, щоб зміни CDN-фото не створювали хибних відмінностей; геометрія, типографіка та блоки залишаються предметом порівняння.

## Звіти

```powershell
npm.cmd run qa:report
```

Звіти зберігаються в `qa-report/`:

- `playwright-html/` — інтерактивний HTML-звіт.
- `playwright-results.json` — машинозчитуваний результат.
- `site-audits/` — вимірювання адаптивності, тексту та axe-core.
- `test-results/` — скриншоти, відео й trace невдалих тестів.
- `MOOD-QA-SUMMARY.md` — підсумок.

## Візуальний контроль

Кожний viewport зберігає повнорозмірний скриншот сторінки. Це артефакт для порівняння дизайну. Pixel-perfect visual regression baseline ще не ввімкнено: спочатку потрібно затвердити контрольні скриншоти після ручного огляду першого звіту.

## Повний цикл QA

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run qa
```

`npm.cmd test` — серверні та unit-тести, без реальних Telegram-повідомлень.
`npm.cmd run build` — production-збірка.
`npm.cmd run qa` — браузерні, адаптивні, accessibility та UI-тести. Всі надсилання форм мокаються в браузері.

## Інтерпретація читабельності

- Менше 10px у основному тексті, підписах полів або інпутах — критична помилка тесту.
- Менше 14px — попередження в JSON-звіті. Воно не блокує прогін, але потребує візуального перегляду.
- Axe-порушення записуються у звіт; критичні порушення блокують тест.
- Контраст і колір реального фонового зображення слід перевіряти також вручну, оскільки фото/оверлей можуть впливати на фактичну читабельність.

## Обмеження

Playwright desktop emulation не замінює перевірку на фізичних телефонах і планшетах. Браузерні тести використовують Chromium, а не всі браузери користувачів. Зовнішні фото/шрифти залежать від мережевого доступу.
