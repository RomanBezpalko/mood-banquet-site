# Автоматизоване тестування Telegram-модуля MOOD

## Швидкий запуск у Windows PowerShell

У терміналі перейдіть у кореневу папку проєкту — ту, де лежить `package.json` — і виконайте:

```powershell
npm.cmd install
npm.cmd test
```

Або лише наскрізний тест Telegram-модуля:

```powershell
npm.cmd run test:telegram
```

Для повної перевірки перед релізом використовуйте:

```powershell
npm.cmd run security:audit
npm.cmd run qa:security
npm.cmd run qa:production
```

`qa:security` поєднує аудит залежностей із тестами, а `qa:production` збирає production-бандл і перевіряє його через production-сервер.

Після завершення Node.js надрукує підсумок у форматі TAP. Успішний прогін має завершитися без `not ok` та з `fail 0`. Команда `npm test` запускає всі `tests/*.test.mjs` і `tests/security/*.test.mjs`, включно з production/security-перевірками. Вона не запускає допоміжні скрипти з `scripts/`, не звертається до реального Telegram і не надсилає повідомлень.

## Що саме перевіряється

1. Головна сторінка відповідає, а API відхиляє заявку з некоректним ім'ям і телефоном.
2. Менеджер проходить реєстрацію через приватний чат: згода, запит номера, перевірка, що передано саме власний контакт.
3. Другий менеджер також реєструється; його обліковий запис використовується для перевірки розмежування доступу.
4. Заявка з калькулятора надходить в особистий чат та групу менеджерів із кнопкою «Взяти в роботу».
5. Незареєстрований користувач не може керувати заявкою.
6. Зареєстрований менеджер бере заявку в роботу; бот надсилає контакт гостя методом `sendContact`.
7. Інший менеджер не може зафіксувати результат дзвінка, який закріплений за першим менеджером.
8. Перевіряються результати «Не відповів», «Передзвонити пізніше» та «Дзвінок здійснено».
9. Повторна спроба надсилає нову картку контакту й видаляє попередню, щоб контакти не дублювалися.
10. Перевіряються нагадування про перший дзвінок (SLA) та повторний дзвінок, включно із захистом від повторного SLA-нагадування.
11. Перевіряються завершення зі статусами «Підтверджена» та «Відхилена».
12. Перевіряються розгортання історії дій і запис збережених заявок/менеджерів у JSON-файли.

## Перевірка номера телефону

У наборі є окремі unit-тести для фіксованого префікса `+380`, рівно 9 національних цифр, видалення літер/символів у полі та серверного відхилення неповних або сторонніх номерів.

## Безпека автоматичного тесту

- Тест запускає тимчасовий сервер на `127.0.0.1` і локальну імітацію Telegram Bot API.
- Використовуються тестовий токен, тестові `chat_id` та окрема тимчасова папка даних ОС.
- Реальний Telegram, реальні менеджерські чати, `.env` і папка `data/` не використовуються та не змінюються.
- `MOOD_TEST_MODE` встановлюється тільки дочірньому процесу тесту. Тестові endpoints `/__test/*` недоступні у звичайному режимі. Тестові значення змінних середовища мають пріоритет над значеннями `.env`, а Telegram API спрямовується на локальну імітацію.
- У тестовому режимі сервер дозволяє запуск лише на localhost і вимикає реальний планувальник нагадувань; нагадування викликаються керовано тестом.

## Перевірка з реальним Telegram

Автоматизований набір перевіряє бізнес-логіку на імітації Bot API й не відправляє повідомлення в реальну групу. Після нього можна окремо виконати:

```powershell
npm.cmd run telegram:test
```

Лише ця команда (`scripts/telegram-delivery-check.mjs`) надсилає тестове повідомлення в реальні отримувачі, вказані у `.env`. Виконуйте її свідомо, щоб не засмічувати робочу групу.

Повну ручну перевірку реальної Telegram-групи (натискання кнопок у клієнті, нативне відображення контактів, фактичне відкриття дзвінка на телефоні) слід провести окремо після автоматизованих тестів.

## Вимоги

- Node.js із вбудованим test runner (`node --test`; рекомендовано Node.js 20 або новіший).
- Встановлені залежності проєкту (`npm.cmd install`).
- Додаткові тестові npm-пакети не потрібні.
